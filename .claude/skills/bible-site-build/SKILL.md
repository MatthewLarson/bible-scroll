# Build modes (run in `bible/`)
- `node tools/build.js --check <id>[/<part>]`: validate only. `VERBOSE=1` prints warnings. Target: 0 and 0.
- `node tools/build.js`: draft build of everything into `site/`, reading lane proposals too. Prints `skip` for a
  book with errors (usually one still being written) and regenerates `PROGRESS.md`.
- `node tools/build.js --publish`: public build into `public/`. Leaves out books whose reviews lack a filled
  `## Fixes applied`, and ignores `content/proposals/` (so a lane book that depends on proposed topics fails
  until the proposals are merged: merge first, see `/publish`).
- Preview: `python3 -m http.server 8766 -d site` (or `-d public`), then http://localhost:8766. The app is
  `app/shell.html` + `app/app.js` + `app/base.css`; data loads from `data/` per book on demand.

# Files
- Generated, never edit: `texts/` (from `tools/texts.py` and `tools/works-texts.py`), `site/`, `public/`, `PROGRESS.md`.
- Authored: `content/`. Atlas harvests (`content/atlas/<id>.json`) are raw and never hand-edited; fixes go in
  `content/atlas/corrections/<id>.json` and global point fixes in `content/atlas/points.json`.
- Revelation: `content/books/Rev/` is generated by `tools/import-rev.js` from `revelation/`; change it through
  `content/overlays/Rev.json` or the source files, then re-import.

# Common errors
- `unknown topic "x"`: the topic core does not exist (or exists only in a proposal and you ran `--publish`).
  Search `content/topics/` and `content/proposals/*/topics/` (titles and `aka`) before creating one.
- `missing verse c:v`: a verse line is missing or out of order in plain.txt.
- anchor not found / partial overlap: a note, gloss or variant anchor is not an exact substring of the verse, or
  two anchors overlap partly (nesting is fine). A note cannot share its anchor with a variant.
- unknown source key: define it in the part's sources.json, or reuse the existing key for that work.
- `quotes X as "...", which is not the site's Plain wording`: update the quote to the current Plain.
- bare reference inside another book's brackets: write the book name on every reference.
Fix the cause (in content, or in build.js/app if the tool is wrong); never hide a real problem.

# Deploying
