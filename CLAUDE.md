# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

# The Bible Scroll

A study website for every book of the Bible (and the books outside it), built for Matt. Each book gets a
Plain English Translation made from the original languages, color-coded notes woven into the text, chapter
commentary, textual variants, topic pages, maps, "who it was for and why" cards and "Where Christians differ"
cards, all in a hand-drawn scroll look. It grew out of a single Revelation study (`revelation/`).

There is no database. Everything is a folder of JSON documents. Read `bible/PLAN.md` for the architecture and
`bible/STYLE.md` for the writing rules before changing content.

## What Matt wants (keep to this everywhere)

- The site's own translation is named the **Plain English Translation**. Always write the full name in content, briefs and messages, never bare "the Plain" (Matt, 2026-10-30). Files and data keys stay `plain.txt` / `plain`.
- Main text in modern American English at about an 8th-grade reading level, translated from the original
  Hebrew, Aramaic and Greek, citing common translations and above all the original-language texts.
- Every interpretive view presented fairly: literal and figurative, Jewish and Christian, traditional and
  critical. Consensus labeled as consensus, with who dissents.
- Denominational views side by side (Catholic, Orthodox, Lutheran, Reformed, Baptist, and the rest),
  especially where they conflict, as `traditions` cards. Never rank them.
- Who each book, sermon, parable, letter, prophecy and law was first for, and why (book.json `audience`,
  chapters.json `settings`). This matters most for the New Testament and Jewish law.
- The most trustworthy original-language sources, with variant notation: the readings, their witnesses, which
  one the Plain English Translation follows and why.
- One topic page per subject across the whole Bible, filterable to the passage just read, with a full-view
  toggle. Maximum cross-referencing. Topic kinds: Ideas, People, Places, Symbols, Words, Events, Studies, Science,
  Creatures. The site must never show exactly 666 topics (Matt, 2026-10-30: the number's religious weight); the full
  build errors on it, so add or merge a topic rather than publish that count.
- Likely mistranslations and common misreadings pointed out, with the Hebrew or Greek.
- Original theories and cross-references welcome, always clearly labeled as Claude's theory (`spec`).
- Three tiers of canon: (1) the 66 books; (2) books some churches hold as Scripture (deuterocanon, Orthodox
  extras, 1 Enoch and Jubilees for the Ethiopian church), always labeled with who accepts them; (3) works in no
  church's Bible, with the full "not widely accepted" treatment (provenance, why rejected, where the Bible
  uses them, a labeled reliability analysis, how to read them). Non-canonical works are styled differently.
- Writings of other peoples and religions (tier `world`, starting with Atrahasis), translated from their own
  languages for context, interest and to show how other cultures told the Bible's stories. Read from a Christian
  standpoint: described fairly, judged with the Bible as the measure, connections and possible same-person
  identifications weighed, never arguing against the LORD being God or Jesus his Son (`tools/agent-writer-world.md`).
- After each book (or part), a SEPARATE agent does a hostile review, and the fixes are applied before publishing.
- Look: ancient manuscript, hieroglyphics, cave drawings and modern art, everything sketched onto a scroll, no
  sharp-edged square images. Openly licensed art when available; otherwise original inline SVG, or ChatGPT image
  prompts (results go in `images/`).
- Fix the cause of a problem; never code around it or hide it in content.

## Layout

```
bible/                  the whole-Bible site (the current work)
  PLAN.md STYLE.md      architecture, writing rules
  PROGRESS.md           GENERATED by the build from content/books/<id>/progress.md. Never edit.
  app/                  shell.html, app.js, base.css (the site's front end)
  tools/                build.js, literal.js, refs.js, texts.py, works-texts.py, dss.py, lxx.py, fetch scripts
                        agent-*.md = the agent briefs (single source of truth for each agent's rules)
                        brief-<id>.md = per-book briefs (parts, lenses, places needing full treatment)
                        lanes.md = who owns which shared files
  texts/                GENERATED source texts (Hebrew, Greek, Ge'ez, English, cross refs, auto variants). Never edit.
  content/              AUTHORED. books/<id>/ (or books/<id>/parts/<a>-<b>/), topics/, atlas/, terms.json,
                        sources.json, works.json, overlays/, proposals/<lane>/
  site/  public/        BUILT (not in the zip; created by the build)
revelation/             the original Revelation scroll (imported into bible/ by tools/import-rev.js; never edit
                        bible/content/books/Rev directly, use content/overlays/Rev.json)
images/                 ChatGPT image results by book
notes/                  decision logs carried over from the cloud project (terms, text policies, lane state)
.scratch/  .cache/      scratch files and downloaded upstream sources (git-ignored)
```

Book ids are STEPBible three-letter codes (Gen Exo ... Rev). Judith is `Jdt` because Jude is `Jud`; Judges is `Jdg`.

## Commands (run from `bible/`)

- `node tools/build.js --check <id>` or `--check <id>/<part>`: validate one book or part, write nothing.
  `VERBOSE=1` shows warnings. A book is only done at 0 errors AND 0 warnings.
- `node tools/build.js`: full draft build into `site/` (prints `skip` for books with errors).
- `node tools/build.js --publish`: build only reviewed books into `public/` (the real website).
- `node tools/serve.js` (or `node tools/serve.js public 8777`): view the site at http://localhost:8766. Use this, not a
  plain static server: addresses are real paths (/Gen/1/2, /topics), so every path must be answered with index.html.
- `node tools/literal.js <id> <chapter>` or `<id> <c:v-v>`: the word-by-word literal line every verse starts from.
  For Akkadian books (Atrahasis): `python tools/akk-literal.py <id> <chapter>`.
- `node tools/atlas-verses.js <id>`: verse lists for the atlas harvest.
- `python tools/logos.py`: remake the site's logos and icons (`app/img/`, WebP; PNG only for the iOS icon and link
  preview) from the designer's files in `images/Logos/`. Rerun after a logo changes; the build copies `app/img/` to `img/`.
- `node tools/import-rev.js`: re-import Revelation after editing `revelation/` or `content/overlays/Rev.json`.
- Regenerating `texts/` is rarely needed: `sh tools/fetch.sh && python3 tools/texts.py` (66 books),
  `sh tools/works-fetch.sh && python3 tools/works-texts.py` (books outside the 66),
  `sh tools/world-fetch.sh && python tools/world-texts.py` (writings of other religions, from SEAL). Downloads go to `.cache/dl`
  (override with `DL=/path`). `tools/dss.py` and `tools/lxx.py` have one-time setup steps in their headers.

There is no test suite and no package to install: `--check` is the test. It exits 1 on any error and takes well
under a second per book. The full build also prints `skip <id>` for books with errors and leaves them out of
`site/` rather than failing.

**On this Windows machine**: `python3` is the Microsoft Store stub and does nothing; use `python` (3.14). Run the
`VERBOSE=1 node ...` and `sh tools/*.sh` forms in the Bash tool (Git Bash); in PowerShell use
`$env:VERBOSE=1; node tools/build.js --check <id>`.

## How the build fits together

`tools/build.js` is the whole back end and also the validator; read its comments before changing content rules.

- A book is `content/books/<id>/` (book.json, progress.md, and either the content files or `parts/<a>-<b>/`
  folders, zero-padded chapter ranges, each with its own plain.txt, notes/variants/glosses/chapters/topics/
  sources.json and review.md). The build joins parts in order; the site never sees them.
- Draft builds and `--check` overlay `content/proposals/<lane>/` (terms, topics, works, points) on the shared
  files; `--publish` ignores proposals, so anything not merged by the lead is absent from `public/`.
- `--publish` includes a book only when every part's review.md has a non-empty `## Fixes applied` (Revelation's reviews
  are `content/overlays/Rev-review-*.md`). The same test sets each book's "reviewed" or "in review" label on the site.
- The build validates keys (sources, topics, works, TRADITIONS, note types), quote-matching against other books'
  Plain English Translation, and atlas data, then writes `site/data/` (per-book JSON, topic shards, reverse "cited by" index) and
  `site/index.html` = `app/shell.html` + `base.css` inlined + `tools/refs.js` + `app/app.js` in one file. The
  front end is a single page routed by real paths (`/Rut/3/9`, `/topic/<id>?from=Rut/3`, `/topics`, `/library`;
  `<base href="/">` keeps `data/` and `img/` working at any depth, and Render rewrites every other path to index.html); `refs.js` is shared by the
  build and the browser to parse references.
- The public site is **Codex Collection** (codexcollection.com), a free study tool that is not commercial and never will be
  (Matt, 2026-10-30). So sources under non-commercial terms (such as CC BY-NC) can be used, and SEAL's Akkadian is shown with credit. Its own pages come from `content/pages/home.md` and
  `mission.md`, `content/articles/<id>.md` (Markdown under a `key: value` header; `status: draft` stays out of
  `public/`; `_template.md` shows the fields) and `content/releases/<date>.json`, written by `tools/release.js` at each
  `/publish`. The full build validates them (`--check` does not).
- It regenerates `PROGRESS.md` from each book's progress.md on every run.
- JSON reads are retried because parallel agents may be mid-write; that's expected, not a bug to remove.

`.claude/` holds the agents (thin wrappers around `tools/agent-*.md`), the slash commands and the skills
(`book-pipeline`, `bible-translation`, `bible-site-build`, `canon-tiers`); change rules in the briefs, not the
wrappers. `.claude/settings.json` denies edits to `bible/texts/**` and `bible/PROGRESS.md`.

## The pipeline for one book

Use the slash commands; each one follows these steps.

1. **Plan** (`/plan-book <id>`): write `tools/brief-<id>.md` (parts, lenses fixed up front, who owns book.json,
   key terms, places needing full treatment, model books), create `content/books/<id>/progress.md`
   (`Status: writing`), harvest the atlas.
2. **Write** (`/write-book <id>`): one `book-writer` agent per part, in parallel. Writers follow
   `tools/agent-writer.md` (plus `agent-writer-works.md` for books outside the 66, plus `brief-nt.md` for the New
   Testament) and the book brief. Every verse starts from `literal.js`, then a drift audit against NIV/ESV done
   in the head only (never write their text out).
3. **Hostile review** (`/review-book <id>`): one `hostile-reviewer` agent per part, never the writer. It writes
   `review.md` and never edits content.
4. **Fix** : one `review-fixer` agent per part applies the findings and fills `## Fixes applied`. A book counts as
   reviewed only when every part's review.md has a non-empty `## Fixes applied` (the build checks this).
5. **Atlas** (`/harvest-atlas <id>`): `atlas-harvester` agent, Bible Atlas MCP tools. The harvest file
   `content/atlas/<id>.json` is never hand-edited; fixes go in `content/atlas/corrections/<id>.json`.
6. **Align and hand over**: cross-part alignment (parallel wording, term consistency, quotes between books),
   `VERBOSE=1 --check <id>` at 0/0, progress.md `Status: reviewed, ready`.
7. **Publish** (`/publish`): merge `content/proposals/*/`, sync quotes, full build, `--publish`, view, deploy.

`traditions-writer` and `audience-writer` agents add "Where Christians differ" and "who it was for" cards to
books written before those features existed.

## Rules that have bitten before

- `texts/` and `PROGRESS.md` are generated. Edit `content/books/<id>/progress.md` (first line `Status: ...`).
- Key terms are rendered the same across the Bible: read `content/terms.json` and `content/proposals/*/terms.json`
  before translating. Changing an existing term needs a "why".
- One topic per subject. Search `content/topics/` and `content/proposals/*/topics/` (titles and `aka`) first.
- A note that quotes another book's verse uses that verse's current Plain English Translation exactly; the build warns otherwise.
- Write the book name on every reference to another book; a bare `c:v` means the current book.
- Never invent a source, quotation, manuscript reading or find. Source keys are global; reuse existing keys.
- Never rely on memory for a checkable detail (witnesses, numbers, quotations, dates, coordinates, what a named
  scholar or church says): check it in this session in something actually opened, or leave it out. Hedges such as
  "as reported" or "not rechecked" are not allowed in content (STYLE.md rule 2). This binds writers, reviewers,
  fixers and the lead. The earlier briefs allowed such hedges, so about 1,300 are already in content.
- Writings outside the 66 are named as in `content/works.json`, never presented as Scripture without saying for whom.
- Tradition names are fixed: TRADITIONS in `tools/build.js`.
- Write long JSON with a script (`json.dump(..., ensure_ascii=False, indent=1)`) and re-read it.
- Writers keep scratch files in `.scratch/<book>-<part>/`, never generic names shared with other writers.
- The NIV can't be included (Biblica's limits); link to Bible Gateway instead. No copyrighted translation text in content.
- Agents run in parallel on different parts: never edit another part's folder or another book's topic contributions.

## Lanes

In the cloud project, several threads wrote at once (lead: Genesis–Song of Songs + Revelation; prophets:
Isaiah–Malachi; nt: Matthew–Jude; works: books outside the 66), and only the lead edited shared files. Locally
this one session is the lead. The per-book briefs still tell prophets/nt/works writers to put shared changes in
`content/proposals/<lane>/`; keep that, and merge the proposals during `/publish` (see `tools/lanes.md`).

Where each book stopped is in `README.md` ("Resume points") and each book's `progress.md`. Decision logs from the
cloud project are in `notes/`.
